## 二、HDC 2026 鸿蒙小艺 Agent 架构事实(原文)

> 来源:爱范儿《HDC 2026 深度解构:鸿蒙全面向 Agent 架构演进,小艺做了这三件事》(2026-06-12)
> 注:原文未公开发布 API 完整规格,以下事实均出自该文直接引述,**[HDC原文]** 标记

### 2.1 鸿蒙智能体框架 HMAF 2.0 [HDC原文]

- **官方名字**:Harmony Agent Framework 2.0(以下简称 HMAF 2.0)
- **协议栈**:
  - A2A 协议升级版(端侧直连支持)
  - A2UI 协议(动态 UI 渲染)
  - MCP 兼容(已在 Anthropic 生态开发工具的团队可直接对接)
- **调度模式**:"意图即服务" —— 用户说一句话 → 小艺拆解意图 → 调度多个 Agent/Skill 协同完成
- **复杂任务成功率**:原文称"90% 以上"
- **装机数据**:
  - 小艺 DAU 1.8 亿
  - 日均唤醒 30 亿次

### 2.2 4 种接入方式 [HDC原文]

原文原话:"开放了多种接入方式:Agent、Skill、MCP、意图框架等"。

| 方式 | 定位 | 典型案例 | zhishe 是否选 |
|---|---|---|---|
| **Agent** | 完整对话决策的第三方智能体 | 东方财富"妙想"、叮咚买菜 Agent | **候选** |
| **Skill** | 单个能力/工具封装 | 各种工具组件 | 备选 |
| **MCP** | 已在 Anthropic 生态开发工具的团队按 MCP 协议对接 | Claude 生态工具 | **候选** |
| **意图框架** | 基于用户一句话意图的轻量服务分发 | 系统级意图识别 | 不选 |

### 2.3 Skill vs Agent 核心区别 [HDC原文 + 推断]

- **Agent**:独立理解/规划/决策的智能体,有自己的 prompt、记忆、目标
- **Skill**:被 Agent 或小艺调用的能力/工具模块,本身不做主决策

**zhishe 应选 Agent 模式**(理由):
- 我们做的是完整装修咨询决策(报价 + 流程 + 避坑),不是单工具
- 千问版 V1.0 已是 Agent 模式(发布在百炼的"知设 AI 装修顾问"应用)
- 战略上"主体 + 多外壳"架构,小艺版做外壳,主体决策仍由 zhishe-a2a 完成 [PROJECT_CONTEXT.md]

### 2.4 上架流程 [HDC原文]

- **上架平台**:小艺开放平台 `developer.huawei.com`
- **生态规模**:已有 2000+ 鸿蒙智能体、500+ 精选伙伴 Skills
- **接入流程**:注册华为开发者联盟 → 实名认证 → 创建智能体 → 调试 → 提交审核

### 2.5 分布入口 [HDC原文]

小艺 Agent 上架后,用户从 5 个入口可触达:

| 入口 | 性质 | 用户行为 |
|---|---|---|
| 智能体市场 | 类应用商店 | 主动搜索"装修" |
| 小艺搜索 | 搜索框 | 主动搜"知设装修顾问" |
| 小艺建议 | 系统级推送 | 被动推荐 |
| 全场景设备(手机/平板/车机/PC/智慧屏/穿戴) | 鸿蒙生态多端 | 跨设备调用 |

### 4.2 协议适配细节

#### MCP 协议 [HDC原文 + 行业规范]
- **协议版本**:2024-11-25(Anthropic 提出)
- **传输**:JSON-RPC 2.0 over HTTP / SSE
- **端点设计**:
  - `/mcp`(stdio 风格,调试用)
  - `/mcp/sse`(Server-Sent Events,小艺主推)
  - `/mcp/http`(HTTP 请求-响应,兜底)
- **暴露 3 个 tools**:

| Tool 名 | 功能 | 触发场景 |
|---|---|---|
| `get_decoration_quote` | 装修报价估算(调用 `app/services/quote.py`) | 用户说"我家 90 平装修多少钱" |
| `get_decoration_advice` | 装修流程/避坑咨询(走 LLM + 知识库) | 用户问"装修流程是什么" |
| `check_decoration_pitfalls` | 装修避坑检查(走 `data/knowledge.json` 22 条铁律) | 用户说"装修要注意什么" |

#### 华为账号 OAuth 2.0 [HDC原文 + 待核实具体文档]
- **授权端点**:`https://oauth-login.cloud.huawei.com/oauth2/v3/authorize` [待核实:具体 URL 以 developer.huawei.com 官方文档为准]
- **Token 端点**:`https://oauth-login.cloud.huawei.com/oauth2/v3/token` [待核实]
- **模式**:Authorization Code(授权码模式,标准 OAuth 2.0)
- **需要的 client_id / client_secret**:用户注册企业开发者账号后,在开发者后台创建应用获得 [待核实:具体资质清单见 10.3]

#### HMAF 端侧直连 [HDC原文 + 待核实]
- 原文称支持"端侧直连",需要华为账号 + 设备 ID
- **普通账号默认走云端调度**,无需设备 ID 即可上架
- **端侧直连是 V1.4 优化项**(提升响应延迟、降低云端压力),V1.3 不做

## 五、能不能直接上小艺?

### 答案:能,但有 2 个前提必须满足。

---

### 前提 1:企业认证(必须用户本人,1-3 天)

- **流程**:`developer.huawei.com` → 注册企业账号 → 营业执照 + 对公打款
- **法人代表**:**你**(装修公司法人,不可代办)
- **时间**:1-3 天
- **风险**:若营业执照主体与小艺注册主体不一致,会驳回 [待核实:具体驳回率]

---

### 前提 2:小艺版 LLM 不是 Qwen(战略冲突,需用户决定)

**冲突点**:
- 用户原话(2026-06-13 战略对齐):"主体用途不变,是要接入千问 AI 大模型的" [PROJECT_CONTEXT.md]
- 小艺版实际:小艺是 OS 系统级大脑,自带 Pangu / DeepSeek 大模型,小艺调度你的 Agent 时,**调的是小艺自带的 LLM,不是 Qwen** [HDC原文]

**2 个解法对比**:

| 维度 | 解法 A(务实派) | 解法 B(保守派) |
|---|---|---|
| LLM 选型 | 小艺自带 Pangu/DeepSeek | 小艺 → 你的 MCP 端点 → 你的后端调 Qwen → 返回 |
| 延迟 | 低(小艺内循环) | +1-2s(绕一圈) |
| 鉴权 | 华为账号 OAuth(标准) | 华为账号 OAuth + Qwen API Key(你自己的) |
| 上架难度 | 低(标准 Agent 模式) | 高(可能触发"非内置 LLM"审核加严) |
| 主体用途 | 部分变(决策逻辑不变,底层 LLM 变) | 100% 不变(Qwen 仍在) |
| 风险 | 用户战略诉求"必须 Qwen"被破坏 | 小艺可能限制外部 LLM 调用频次 |
| 长期成本 | 0(用小艺自己的 LLM) | 按 Qwen 调用量付费 |

**我推荐解法 A**,理由:
1. 小艺明牌不让外部大模型当主(否则所有 Agent 都接 GPT-4,小艺生态没意义)
2. 硬塞 Qwen 绕一圈,小艺审核可能直接驳回,1 周上架周期白等
3. 主体业务逻辑(装修咨询决策)不变,变的是底层 LLM —— 用户实际感受到的"装修顾问"质量不变
4. 战略上 V1.4 抖音/智谱/豆包版可继续按 Qwen 走,小艺版用 Pangu 是合理的"因地制宜"

**用户决策点**:接受解法 A 即开始;坚持解法 B 则需先和小艺商务沟通白名单,周期拉长到 1 个月起。
