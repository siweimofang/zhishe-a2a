## 二、算法安全管理制度建设情况

### (一)算法安全管理制度

#### 1. 算法安全管理办法

本公司已制定《知设装修顾问算法安全管理办法》,明确:
- 算法的研发、上线、运营、变更、终止全生命周期安全管理
- 算法安全责任分工
- 算法安全风险评估流程
- 算法安全事件处置流程

#### 2. 算法变更管理制度

明确算法重大变更的定义、审批流程、变更后的评估要求:
- 触发条件:算法模型版本变更、数据来源变更、服务范围变更等
- 审批流程:技术负责人评估 → 算法安全责任人审核 → 法定代表人批准
- 评估要求:变更后 30 天内开展专项自评估

### (二)算法自评估制度

#### 1. 评估频率

- **定期评估**:每年至少 1 次全面自评估(年初)
- **变更评估**:算法发生重大变更时,30 天内开展专项评估
- **应急评估**:发生算法安全事件后,15 天内开展事件复盘评估

#### 2. 评估内容

依据《算法安全自评估报告模板》的 6 大模块:
1. 算法基本信息
2. 算法情况(算法流程、数据、模型、干预策略、结果标识)
3. 服务情况
4. 风险研判
5. 风险防控情况
6. 安全评估结论

#### 3. 评估流程

```
评估需求识别 → 组建评估小组 → 资料收集 → 现场评估
   → 形成评估报告 → 算法安全责任人审核 → 整改闭环 → 归档留存
```

#### 4. 评估结果应用

- 评估结论为"风险可控" → 维持当前运营,持续监测
- 评估结论为"需整改" → 30 天内完成整改,重新评估
- 评估结论为"需重大调整" → 暂停服务,60 天内完成架构调整

#### 5. 评估记录留存

所有评估报告纸质 + 电子版本至少留存 **3 年**,以备监管检查。

### (三)算法监测制度

#### 1. 监测内容

- **算法输出监测**:实时监控算法输出内容,识别违规信息
- **用户反馈监测**:实时接收用户投诉举报
- **系统性能监测**:监控 API 调用成功率、响应时间、错误率
- **数据安全监测**:监控数据访问日志、异常访问行为

#### 2. 监测工具

| 工具类型 | 工具名称 | 监测对象 |
|---|---|---|
| 内容审核 | zhishe-a2a 内置关键词过滤系统 | 违规信息识别 |
| 日志系统 | zhishe-a2a 内置 observability 模块 | 系统运行状态 |
| 用户反馈 | 投诉举报渠道 | 用户反馈 |
| 性能监控 | uvicorn + 自研监控 | API 性能 |

#### 3. 监测频次

- **实时监测**:内容审核、日志系统、性能监控(7×24 小时)
- **每日复盘**:每日 18:00 算法安全责任人检查当日监测数据
- **每周分析**:每周一形成上周算法安全周报
- **每月总结**:每月末形成月度算法安全报告

#### 4. 异常处置

发现异常时按以下流程处置:
```
发现异常 → 算法安全责任人评估 → 严重程度分级
   → 轻微:关键词过滤 + 人工复核
   → 中等:暂停相关服务 + 排查原因 + 修复
   → 严重:全面暂停 + 启动应急预案 + 报告监管部门
```

### (四)算法应急处置制度

#### 1. 应急预案启动条件

- 算法被恶意利用生成大量违法违规内容
- 算法出现重大漏洞导致服务异常
- 发生重大数据泄露事件
- 监管部门通报要求整改

#### 2. 应急响应流程

```
发现事件 → 5 分钟内报告算法安全责任人 → 30 分钟内启动应急预案
   → 暂停相关服务 → 排查原因 → 修复问题 → 重新评估 → 恢复服务 → 事件复盘
```

#### 3. 应急响应时间要求

- **5 分钟内**:初步响应
- **30 分钟内**:完成问题初步定位
- **2 小时内**:完成问题修复(轻微问题)
- **24 小时内**:完成问题修复(中等问题)
- **72 小时内**:完成问题修复(严重问题)

#### 4. 应急演练

每年至少开展 **2 次**应急演练(年中、年末各一次),模拟不同类型安全事件。

#### 5. 事件复盘

每次应急响应结束后 **7 天内**,形成事件复盘报告:
- 事件经过
- 根本原因分析
- 处置过程评估
- 整改措施
- 预防措施

### (五)算法违法违规处置制度

#### 1. 违规行为界定

下列行为视为算法违法违规行为:
- 算法输出违反法律法规的内容
- 算法未按规定添加"AI 生成"标识
- 算法未按规定公示备案号
- 算法未经备案擅自上线
- 算法发生重大变更未及时变更备案

#### 2. 处置原则

- **零容忍**:对违法违规行为零容忍
- **快速响应**:发现违规行为 24 小时内启动处置
- **追溯整改**:追根溯源,举一反三,全面整改

#### 3. 处置流程

```
发现违规 → 评估严重程度 → 启动处置
   → 轻微:警告相关责任人 + 立即整改 + 内部通报
   → 中等:暂停相关功能 + 公开致歉 + 报告监管部门
   → 严重:全面暂停服务 + 主动报告 + 配合调查
```

#### 4. 责任追究

- 直接责任人:警告、通报批评、解除劳动合同
- 算法安全责任人:承担管理责任
- 法定代表人:承担领导责任

### (六)个人信息保护制度

#### 1. 个人信息收集

- 仅收集用户主动提供的信息(问询内容、城市等)
- 不收集与服务无关的信息
- 收集前明确告知收集目的、方式和范围

#### 2. 个人信息使用

- 仅用于本次对话,不留存(对话结束后清除)
- 不用于用户画像、定向推送等
- 不与第三方共享

#### 3. 个人信息存储

- HTTPS/TLS 1.3 加密传输
- 存储加密(如有)
- 存储期限:本次对话结束后清除

#### 4. 用户权利保障

- 知情权:在产品显著位置公示个人信息处理规则
- 决定权:用户可拒绝提供非必要信息
- 删除权:用户可要求删除已提供信息

### (七)网络与信息安全管理

#### 1. 网络安全

- HTTPS/TLS 1.3 加密传输
- 防火墙 + WAF 防护
- DDoS 防护(Cloudflare)

#### 2. 系统安全

- 服务器安全加固
- 定期漏洞扫描
- 及时安装安全补丁

#### 3. 数据安全

- 数据传输加密
- 数据存储加密
- 数据备份与恢复机制

### (八)信息系统安全保密制度

#### 1. 保密范围

- 算法核心技术细节
- 用户隐私数据
- 系统安全配置

#### 2. 保密措施

- 与员工签订保密协议
- 访问权限分级管理
- 离职员工权限及时回收
- 工作场所保密管理

#### 3. 泄密处置

发现泄密事件,立即启动应急预案,追查责任人,依法追责。

### (九)信息安全风险应急预案

#### 1. 风险分类

- **高风险**:数据泄露、系统被入侵
- **中风险**:服务异常、性能下降
- **低风险**:小范围故障

#### 2. 应急响应

- 高风险:立即启动预案,1 小时内报告监管部门
- 中风险:启动预案,24 小时内处理完毕
- 低风险:常规处置,72 小时内处理完毕

#### 3. 预案演练

每年至少 2 次应急演练,提升应急响应能力。

## 四、技术保障措施

### (一)内容安全

1. **关键词过滤系统**:覆盖政治敏感、色情低俗、暴力血腥、虚假信息等 10000+ 关键词
2. **深度学习审核**:使用小型分类模型对疑似违规内容进行二次审核
3. **人工抽检**:每日人工抽检 100+ 算法输出内容

### (二)数据安全

1. **传输加密**:HTTPS/TLS 1.3
2. **访问控制**:基于角色的访问控制(RBAC)
3. **日志留存**:所有访问日志留存至少 6 个月

### (三)模型安全保障

1. **版本管理**:每次模型更新都有版本号,记录在案
2. **回滚机制**:发现问题可快速回滚
3. **A/B 测试**:新版本先小流量测试,再全量上线
