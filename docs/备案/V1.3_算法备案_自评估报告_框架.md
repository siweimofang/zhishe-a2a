## 一、算法情况

### (一)算法流程

**算法流程图**:

```
[用户输入] → [客户端/智能体入口] → [zhishe-a2a 后端接收]
   ↓
[请求预处理] → [意图识别] → [分流到对应能力模块]
   ↓
┌─────────────────┬─────────────────┬─────────────────┐
↓                 ↓                 ↓
[装修报价模块]   [施工标准模块]   [建材品牌模块]
↓                 ↓                 ↓
[知识库检索]    [知识库检索]     [知识库检索]
↓                 ↓                 ↓
[DeepSeek-v4-pro API 调用] → [响应生成]
↓
[结果标识(显式+隐式)] → [内容审核] → [返回用户]
```

**流程说明**:

| 节点 | 描述 | 输入 | 输出 |
|---|---|---|---|
| 用户输入 | 用户通过小艺智能体、千问 APP、微信公众号等渠道发起装修咨询 | 自然语言文本 | 原始请求 |
| 请求预处理 | 清洗用户输入,识别意图(报价/标准/建材/品牌) | 原始请求 | 清洗后请求 + 意图标签 |
| 意图识别 | 基于小型分类模型识别用户需求类型 | 清洗后请求 | 意图分类结果 |
| 能力分发 | 根据意图路由到对应的专业能力模块 | 意图分类结果 | 目标能力模块 |
| 知识库检索 | 每个模块对应一个专业装修知识库(RAG) | 用户问题 | 检索结果 |
| 大模型调用 | 结合知识库检索结果,调用 DeepSeek-v4-pro API 生成回答 | 检索结果 + 用户问题 | 初步回答 |
| 结果标识 | 为生成内容添加"AI 生成"显式标识 + 隐式元数据 | 初步回答 | 标识后回答 |
| 内容审核 | 通过关键词过滤 + 人工抽检确保内容合规 | 标识后回答 | 合规回答 |
| 返回用户 | 最终响应返回给用户 | 合规回答 | 用户看到 |

**示例输出**:

#### 1. 基础模型

- **模型名称**:DeepSeek-v4-pro
- **模型版本**:v4.0
- **模型类型**:基于 Transformer 架构的大语言模型
- **参数规模**:千亿级参数

#### 2. 本算法的封装层

本算法在 DeepSeek-v4-pro 基础上,增加了以下模块:

| 模块 | 用途 | 实现方式 |
|---|---|---|
| 意图识别模型 | 识别用户需求类型(报价/标准/建材/品牌) | 小型分类模型,本地部署 |
| 装修知识库 | 提供装修专业知识 | RAG(检索增强生成),本地存储 |

| 内容审核模块 | 过滤违规内容 | 关键词过滤 + 深度学习分类 |

### (四)干预策略

#### 1. 预处理

| 措施 | 描述 |
|---|---|
| 输入清洗 | 去除特殊字符、控制字符 |
| 输入长度限制 | 最多 2000 字符 |
| 敏感词预检测 | 政治敏感、色情低俗等关键词预检测 |

#### 2. 后处理

| 措施 | 描述 |
|---|---|
| 输出长度限制 | 最多 3000 字 |
| 输出格式校验 | 确保 JSON 结构正确 |
| 输出合规检查 | 二次内容审核 |
| "AI 生成"标识 | 显式标识 + 隐式元数据 |

#### 3. 内容审核

**审核方式**:机器审核 + 人工抽检

**审核规则**(关键词库):
- 政治敏感关键词:100+ 词
- 色情低俗关键词:500+ 词
- 暴力血腥关键词:200+ 词
- 虚假信息关键词:300+ 词
- 营销黑话关键词:200+ 词

**审核流程**:
```
关键词过滤(第一道) → 深度学习分类(第二道) → 人工抽检(第三道)
```

#### 4. 应急预案

- 发现违规输出立即拦截
- 触发关键词熔断机制
- 人工复核后方可放行
- 严重违规立即停止服务

### (五)结果标识

#### 1. 显式标识

- 在回答开头添加"AI 生成"标识
- 在回答结尾添加"本回答由 AI 生成,仅供参考,具体施工请咨询专业人士"
- 标识字体加粗,显著可见

**示例**:
> 【AI 生成】
> 沈阳 100 平三室一厅基础装修...
> 【本回答由 AI 生成,仅供参考,具体施工请咨询专业人士】

#### 2. 隐式标识

- 在响应数据中嵌入生成时间戳 + 算法版本号 + 备案号(待获取)
- 使用水印技术嵌入不可见标识
- 支持溯源,可追溯到具体生成时间 + 算法版本

## 三、风险研判

### (一)算法滥用

**风险描述**:用户可能利用本算法生成不当内容,例如:
- 编造虚假的装修报价(可能误导消费者)
- 编造虚假的施工标准(可能误导施工方)
- 编造虚假的品牌评测(可能构成商业诋毁)
- 生成违法违规的装修方案(违建等)

**影响分析**:
- 可能误导装修决策
- 可能损害消费者权益
- 可能引发合同纠纷
- 严重时可能涉及法律责任

### (二)算法漏洞

**风险描述**:算法本身可能存在漏洞,导致在特定输入下产生错误输出,例如:
- 装修报价误差过大
- 施工标准引用错误
- 本地建材信息过时

**影响分析**:
- 影响用户信任
- 可能产生售后纠纷

### (三)算法恶意利用

**风险描述**:第三方可能恶意利用本算法,例如:
- 批量调用 API 进行数据爬取
- 恶意构造输入绕过内容审核
- 利用算法进行不正当竞争

**影响分析**:
- 服务资源耗尽
- 内容安全风险
- 商业利益受损

### (四)数据安全风险

**风险描述**:可能发生数据泄露事件,例如:
- 用户问询数据泄露
- 系统日志泄露
- API Key 泄露

**影响分析**:
- 用户隐私泄露
- 系统安全风险

### (五)未成年人保护风险

**风险描述**:未成年人可能使用本算法,可能产生不适合其年龄的内容

**影响分析**:
- 不适合未成年人的装修内容(如商业决策)

### (六)其他风险

无重大其他风险。
