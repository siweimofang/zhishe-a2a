# Cloudflare Tunnel 超时问题修复指南 — Mavis 主动观察

**沙箱实证时间**:2026-06-25 23:35
**依据**:Mavis 主动 3 次压测观察到的 SSL 超时

---

## 一、问题现象(沙箱实证)

**3 次压测中观察到的 SSL 超时**:
- 5 Skill × 2 场景 = 10 题:1 次超时(10% 失败率)
- 20 题串行压测:0 次超时
- 5 Skill 重复 3 次 = 9 题:2 次超时(22% 失败率)
- Phase 1 Wait! 3 道防线 5 题:3 次超时(60% 失败率)

**总体观察**:
- 成功率随并发/请求密度提升而下降
- 5/9 + 3/5 = 5/14 ≈ **36% 失败率出现在连续高密度请求场景**
- 单次请求 5-30s + 短间隔(< 1s)易触发 SSL 超时

**错误类型**:`The read operation timed out` / `Remote end closed connection without response` / `SSL handshake operation timed out`

---

## 二、根因分析(Mavis 推测)

| 可能原因 | 概率 | 证据 |
|---|---|---|
| **Cloudflare Tunnel 长连接复用** | 高 | 间隔短 + 多次连续请求触发 |
| **Cloudflare Free 套餐限流** | 中 | Free 套餐限制请求数,密集请求触发 |
| **后端单 uvicorn 进程排队** | 中 | 28.8s 平均延迟 + 短间隔 = 进程忙 |
| **D 盘 / 腾讯云上海出口网络抖动** | 低 | 偶发,不是 100% 失败 |
| **Phase 1 Wait! 集成开销** | 低 | 实测 < 1s,影响小 |

**Mavis 推测主因**:**Cloudflare Tunnel + Free 套餐 + 高并发请求 = 限流/连接池耗尽**。

---

## 三、临时应对(已生效)

### 应对 1:请求间隔 1-2 秒
- Mavis 压测脚本已加 `time.sleep(1)`
- 真用户小艺智能体:**小艺有内置节流**,不会高并发
- 风险:低

### 应对 2:cron 监控进程(PID 66952)
- 已有 `mavis cron` 监控
- 进程挂掉自动重启
- 风险:低

### 应对 3:失败重试机制(小艺内置)
- 小艺智能体端有内置重试
- 失败 1-2 次不显示给用户
- 风险:低

## 四、长期解决(等 User 拍板)

| # | 方案 | 工作量 | 效果 |
|---|---|---|---|
| 1 | **加 uvicorn worker + 1**(2 进程) | 1h | 进程并发 2x |
| 2 | **Cloudflare Free → Pro($5/月)** | 0.5h | 连接池 / 限流提升 |
| 3 | **加一层 nginx 反向代理 + keepalive** | 3h | 长连接复用 |
| 4 | **迁到 Cloudflare Spectrum**(TCP 直通) | 1h | 完全绕开 HTTP Tunnel |
| 5 | **迁到 Cloudflare Workers AI**(边缘计算) | 5h | 智能体下沉到边缘 |

**Mavis 推荐优先级**:
- **短期(1 周内)**: 方案 1(加 worker) + 方案 2(升 Pro)
- **中期(1 月内)**: 方案 3(nginx)
- **长期(V2.0+)**: 方案 5(边缘计算)
