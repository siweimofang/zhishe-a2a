### 2.2 关键判断(沙箱查证 2026-06-16)

1. **小艺主对话 = 自动调起智能体**:**这是 V1.3 跟 V1.0/V1.1/V1.2 的本质区别**。千问/元宝/豆包主对话都不自动调起;**小艺主对话会按"意图"自动路由到对应智能体**。
2. **"意图即服务"是 V1.3 战略核心**:**用户在小艺主对话说"我想装修"或"装修报价",小艺自动调起"知设 AI 装修顾问"**(无需用户主动搜"装修"或"知设")。
3. **HDC 2026 鸿蒙智能体框架 2.0 = zhishe 多外壳战略的官方背书**:"意图即服务" / "后端统一引擎 + 前端多平台获客" 架构,跟 zhishe 战略 100% 同构。
4. **数据自留 = 强**:**Service Extension Ability 支持挂外部 HTTP API**,**zhishe-a2a 永久 URL 可作为 Service Extension Ability 挂载** → 数据 100% 走自留地(跟 V1.2 扣子工作流路径 A 同思路)。
5. **审核 1-2 周**:**比 V1.0 千问(V1.0 占坑是 5 天审核)慢**,**比 V1.1 元宝(几分钟~数小时)慢很多**;**比 V1.2 扣子(几乎无审核)慢**。V1.3 审核时间预估 1-2 周。

### 2.3 战略意义(HDC 2026 鸿蒙智能体框架 2.0)

| 维度 | HDC 2026 框架 2.0 | zhishe 多外壳战略 |
|---|---|---|
| **架构** | "后端统一引擎 + 前端多平台获客" | "内壳 LLM 动态 + 外壳平台自家" |
| **获客路径** | "意图即服务" | "5 大平台广撒网 + 主对话自动调起" |
| **数据策略** | 自留地(用户数据可自定义后端) | 100% 自留地(zhishe-a2a 永久 URL) |
| **生态定位** | 智能硬件 + 全场景 | 装修 AI 顾问 + 5 大平台 |
| **战略契合度** | **100%** | **100%** |

**结论**:**V1.3 小艺 = HDC 2026 框架 2.0 的"战略级示范应用"**。**zhishe 多外壳战略跟华为智能体框架 2.0 100% 同构**。

## 3. 路径选择(从"自留地"到"小艺主对话")

### 路径 A(主推):HarmonyOS 智能体框架 2.0 + Service Extension Ability 挂 zhishe-a2a

```
[HarmonyOS 设备 10 亿+(手机/平板/车机/智慧屏)]
   ↓ 小艺主对话(1.8 亿 DAU,30 亿次/天)
[小艺智能体框架 2.0 - 意图识别]
   ↓ 关键词"装修" / "报价" / "知设" → 路由"知设 AI 装修顾问"
[Service Extension Ability(华为云函数)]
   ↓ 调"知设装修咨询"节点
[zhishe-a2a 永久 URL https://tunnel.zhishe.top/v1/chat/completions]
   ↓ (内壳 LLM = DeepSeek-v4-pro,知识库 V0.1 注入)
[回传答案]
   ↓
[小艺智能体 → 小艺主对话用户]
```

**优势**:
- **数据 100% 走自留地**(核心战略 — 不锁定任何平台)
- **知识库 V0.1 + prompt V1.6 直接复用**(V1.0 千问 V1.1 元宝 V1.2 豆包 0 损耗)
- **内壳 LLM 永远是 DeepSeek-v4-pro**(动态战略资产,小艺"盘古"只做"意图识别"和"格式转换")
- **主对话自动调起**(跟 V1.0/V1.1/V1.2 唯一不同,1.8 亿 DAU 触达)

**劣势**:
- HarmonyOS IDE 配置(1-2 天,需要 DevEco Studio)
- 华为开发者实名认证(1-3 天)
- 智能体上架审核(1-2 周)

### 路径 B(备选):华为云 Pangu API + 小艺开放平台直接调

```
[小艺 APP 用户]
   ↓ 主动搜"装修" / "知设"
[小艺开放平台智能体广场]
   ↓ 进入"知设 AI 装修顾问"
[华为云 Pangu API 直答]
   ↓ (外壳 LLM = Pangu,知识库传华为云)
[回传答案]
```

**优势**:
- 配置简单(20 min 用户搞定)
- 无需 HarmonyOS IDE(用华为云控制台)

**劣势**:
- **数据 100% 锁华为云**(违背"自留地"战略核心)
- **知识库要上传到华为云**(重复劳动,跟 V1.0/V1.1/V1.2 脱钩)
- **prompt 要在华为云平台重写一份**(跟 V1.0/V1.1/V1.2 维护 4 份)
- **主对话不自动调起**(用户需主动搜)

### 路径 C(不推荐):走华为云 ModelArts(类似百炼的 LLM 平台)

**说明**:**华为云 ModelArts**定位"AI 开发平台",**不开放 C 端智能体独立发布**;**所有"小艺智能体"实质都是智能体框架 2.0 + Service Extension Ability 路径**。**路径 C 不可行**。

### 决策矩阵

| 维度 | 路径 A(Service Extension Ability 挂自留地) | 路径 B(华为云 Pangu 直答) | 路径 C(ModelArts) |
|---|---|---|---|
| 数据自留 | ✅ 强 | ❌ 弱 | ❌ 不可行 |
| 知识库复用 | ✅ 100% 复用 V0.1 | ❌ 需重传 | ❌ 不可行 |
| Prompt 复用 | ✅ 100% 复用 V1.6 | ❌ 需重写 | ❌ 不可行 |
| 主对话自动调起 | ✅ 强(1.8 亿 DAU) | ❌ 弱(用户主动搜) | ❌ 不可行 |
| 装修用户触达 | ✅ 强(自动调起) | 中(主动搜) | ❌ 不可行 |
| 配置工作量 | 大(1-2 天 IDE) | 小(20 min) | 不可行 |
| 实名认证 | 必需(1-3 天) | 必需(1-3 天) | 不可行 |
| 上架审核 | 1-2 周 | 1-2 周 | 不可行 |
| 战略契合度 | ✅ 100%(自留地 + 内壳动态) | ❌ 50% | ❌ 0% |
| 跟 V1.0/V1.1/V1.2 一致性 | ✅ 100% | ❌ 50% | ❌ 0% |

**我的建议**:**路径 A 为主推**。**V1.3 是 5 大外壳中"主对话自动调起"唯一版本,值得花 1-2 天 IDE 配置 + 1-2 周审核**。

## 4. 模型选型

### 4.1 路径 A 下的"内壳/外壳"分工

**关键判断**:路径 A 下,**小艺"盘古大模型"只负责"意图识别 + 格式转换 + 安全审核"**,**真正的"内壳 LLM"还是 DeepSeek-v4-pro**(从自留地走)。

| 模型 | 角色 | 备注 |
|---|---|---|
| **小艺"盘古大模型"** | 外壳 LLM(意图识别 + 格式转换) | 华为云,**几乎不参与答案生成** |
| **zhishe-a2a "DeepSeek-v4-pro"** | **内壳 LLM(答案生成主力)** | 100% 复用 V1.0 |
| **华为云 Pangu(可选)** | 备选(复杂推理) | Service Extension Ability 挂 2 节点 |
| **第三方模型(GLM-5.1 / Kimi / ...) | 备选 | 暂不用 |

### 4.2 路径 B(华为云 Pangu 直答)的"外壳 LLM"直接出答案

| 模型 | 适用场景 | 备注 |
|---|---|---|
| **Pangu(盘古)** | V1.3 路径 B 默认(主推) | 256k 上下文,深度思考,工具调用 |
| **Pangu-Turbo** | 备选(轻量/省钱) | 速度快,但装修深度可能不够 |
| **Pangu-Reasoning** | 备选(复杂推理) | 适合"全案设计"类长推理 |
| **第三方模型** | 备选 | 华为云支持,暂不用 |

### 4.3 选型决策(以主推路径 A 为准)

| 决策 | 选项 | 我的建议 |
|---|---|---|
| 小艺"意图识别" | 盘古(默认) | **YES** |
| 内壳 LLM(zhishe-a2a) | DeepSeek-v4-pro | **YES**(V1.0 已在用) |
| 备选"复杂推理"模型 | Pangu-Reasoning | **可加**(Service Extension Ability 挂 2 节点) |

**说明**:**跟 V1.0/V1.1/V1.2 "内壳 LLM 动态战略资产"理念一致** — **外壳 LLM = 平台自家(小艺=盘古)**,**内壳 LLM = 动态战略资产(当前 DeepSeek-v4-pro)**。
