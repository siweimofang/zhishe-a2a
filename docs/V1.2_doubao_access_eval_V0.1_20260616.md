# V1.2 豆包版接入评估 V0.1

**编制日期**:2026-06-16
**作者**:Mavis
**战略地位**:5 大外壳战略第 2 环(V1.0 千问 → V1.1 元宝 → **V1.2 豆包** → V1.3 小艺 → V1.4 智谱清言)
**配套 commit**:`4e8c41e` V1.1 元宝版"准备就绪"快照

---

## 一句话定位

把"知设 AI 装修顾问"用**字节扣子(coze.cn)生态**发布到**豆包 APP**,复用 V1.0/V1.1 prompt + 知识库,只换**外壳 LLM = 豆包 1.5 Pro**(平台自家品牌大模型)。

## 1. 战略定位(为什么 V1.2 排第二)

| 维度 | 评估 |
|---|---|
| **生态规模** | 字节扣子(国内最大 LLM Agent 生态之一,700+ 插件,12+ 领域) + 豆包 APP(月活亿级) |
| **平台开放度** | **比千问 / 元宝高 1 档** — 扣子"工作流"能力极强,可挂自家 zhishe-a2a 永久 URL 作 HTTP 节点,**真正实现"内壳 LLM 动态 + 外壳 LLM 平台化"** |
| **品牌独立** | 强(豆包主对话不调扣子,用户主动搜"装修"才能找到 → 跟我 V1.0 千问同档,主动曝光) |
| **C 端触达** | 中(豆包 APP 月活亿级,但**主对话不自动调起装修 Agent**,需用户主动进入扣子智能体广场搜索) |
| **装修生态契合** | 中(豆包偏年轻 / 内容创作,装修是决策类咨询 — 内容/调性差异需要 prompt 校准) |
| **变现路径** | 弱(扣子 + 豆包目前**主要靠订阅/插件分销**,C 端问答 + 加微信私域路径不如腾讯元宝) |
| **数据自留** | **强**(扣子支持挂外部 HTTP API,**zhishe-a2a 永久 URL 可作为扣子插件节点** → 数据 100% 走自留地,**跟 V1.0/V1.1 "内壳服务"理念一致**) |
| **审核难度** | 低(扣子审核比腾讯元器宽松,智能体发布无需实名认证,只需扣子账号) |
| **工作量大** | **20-30 min 写文档 + 用户 30-60 min 扣子智能体配置**(比 V1.0 百炼简单,扣子 UI 友好) |

**结论**:**V1.2 排第二** = 战略价值中 / 工作量小 / 数据自留强 / 跟 V1.0 千问 V1.1 元宝形成"千问+元宝+豆包"三巨头覆盖。

### 2.3 关键判断(沙箱查证 2026-06-16)

1. **豆包主对话 ≠ 扣子智能体**: 豆包 APP 主对话用豆包 LLM,**不主动调起扣子智能体**;扣子智能体只暴露在"智能体广场"。

3. **扣子审核极松**:**几乎无审核**,用户主动搜才能找到,适合**快速验证 + 多版本测试**。

## 3. 路径选择(从"自留地"到"豆包 APP")

### 路径 A(主推):扣子智能体 + 工作流挂 zhishe-a2a 永久 URL

```
[豆包 APP 用户]
   ↓ 主动搜"装修" / "知设"
[扣子智能体广场]
   ↓ 进入"知设 AI 装修顾问"
[扣子工作流]
   ↓ 调"知设装修咨询"节点
[zhishe-a2a 永久 URL https://tunnel.zhishe.top/v1/chat/completions]
   ↓ (内壳 LLM = DeepSeek-v4-pro,知识库 V0.1 注入)
[回传答案]
   ↓
[扣子智能体 → 豆包 APP 用户]
```

**优势**:
- **数据 100% 走自留地**(核心战略 — 不锁定任何平台)
- **知识库 V0.1 + prompt V1.6 直接复用**(V1.0 千问 V1.1 元宝的成果零损耗)
- **内壳 LLM 永远是 DeepSeek-v4-pro**(动态战略资产,扣子"豆包 1.5 Pro"只做"外壳"格式转换)

**劣势**:
- 工作流配置需要扣子 UI 操作(用户 30-60 min)
- 扣子平台数据自留需要扣子 Pro 订阅(¥49/月,**有 30 天免费试用,先试用 30 天**)

### 路径 B(备选):纯扣子智能体,豆包 LLM 直答

```
[豆包 APP 用户]
   ↓ 主动搜"装修" / "知设"
[扣子智能体"知设 AI 装修顾问"]
   ↓ (外壳 LLM = 豆包 1.5 Pro 直答,扣子平台知识库)
[回传答案]
```

**优势**:
- 配置极简(20 min 用户搞定)
- 无订阅费(扣子免费版够用)

**劣势**:
- **数据 100% 锁扣子平台**(违背"自留地"战略核心)
- **知识库要上传到扣子平台**(重复劳动,跟 V1.0/V1.1 知识库脱钩)
- **prompt 要在扣子平台重写一份**(跟 V1.0/V1.1 维护 2 份)

### 路径 C(不推荐):走豆包智能体(豆包独立平台)

**说明**:**豆包 APP 不开放第三方智能体独立发布**;所有"豆包智能体"实质都是扣子智能体。**路径 C 不可行**。

### 决策矩阵

| 维度 | 路径 A(工作流挂自留地) | 路径 B(纯扣子) | 路径 C(豆包直发) |
|---|---|---|---|
| 数据自留 | ✅ 强 | ❌ 弱 | ❌ 不可行 |
| 知识库复用 | ✅ 100% 复用 V0.1 | ❌ 需重传 | ❌ 不可行 |
| Prompt 复用 | ✅ 100% 复用 V1.6 | ❌ 需重写 | ❌ 不可行 |
| 配置工作量 | 中(30-60 min) | 小(20 min) | 不可行 |
| 订阅费 | ¥49/月(可试用 30 天) | ¥0 | 不可行 |
| 战略契合度 | ✅ 100%(自留地 + 内壳动态) | ❌ 50% | ❌ 0% |
| 跟 V1.0/V1.1 一致性 | ✅ 100% | ❌ 50% | ❌ 0% |

**我的建议**:**路径 A 为主推**。**先 30 天免费试用扣子 Pro**,验证"工作流挂自留地"路径真跑得通;试用期内**数据自留 100% 不丢**;30 天后根据数据决定是否继续 ¥49/月。

## 4. 模型选型

### 4.1 扣子"工作流"挂 zhishe-a2a 路径(主推)的"外壳 LLM"是平台格式化层

**关键判断**:路径 A 下,**扣子智能体的"豆包 1.5 Pro"只负责"格式转换 + 安全审核"**,**真正的"内壳 LLM"还是 DeepSeek-v4-pro**(从自留地走)。

| 模型 | 角色 | 备注 |
|---|---|---|
| **扣子平台"豆包 1.5 Pro"** | 外壳 LLM(格式转换层) | 扣子默认,**几乎不参与答案生成** |
| **zhishe-a2a "DeepSeek-v4-pro"** | **内壳 LLM(答案生成主力)** | 100% 复用 V1.0 |
| **豆包 Thinking** | 备选(复杂推理) | 工作流可挂,跟 DeepSeek 并联 |
| **第三方模型(GLM-5.1 / Kimi / ...) | 备选 | 扣子支持,但 V1.2 暂不用 |

### 4.2 路径 B(纯扣子)的"外壳 LLM"直接出答案

| 模型 | 适用场景 | 备注 |
|---|---|---|
| **豆包 1.5 Pro** | V1.2 路径 B 默认(主推) | 256k 上下文,深度思考,工具调用 |
| **豆包 Lite** | 备选(轻量/省钱) | 速度快,但装修深度可能不够 |
| **豆包 Thinking** | 备选(复杂推理) | 适合"全案设计"类长推理 |
| **第三方模型** | 备选 | 扣子支持,暂不用 |

### 4.3 选型决策(以主推路径 A 为准)

| 决策 | 选项 | 我的建议 |
|---|---|---|
| 扣子"工作流"默认模型 | 豆包 1.5 Pro | **YES**(默认就够用) |
| 内壳 LLM(zhishe-a2a) | DeepSeek-v4-pro | **YES**(V1.0 已在用) |
| 备选"复杂推理"模型 | 豆包 Thinking | **可加**(工作流挂 2 节点) |

**说明**:**跟 V1.1 元宝版"内壳 LLM 动态战略资产"理念一致** — **外壳 LLM = 平台自家(扣子=豆包)**,**内壳 LLM = 动态战略资产(当前 DeepSeek-v4-pro)**。
