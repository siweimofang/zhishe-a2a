## 2. 扣子"工作流"配置(核心 - 路径 A 主推)

### 2.1 工作流设计(用户 15-20 min 配)

**关键洞察**:**扣子智能体"提示词"只负责"自我介绍 + 路由引导",真正的"答案生成"通过工作流 HTTP 请求节点调 zhishe-a2a 永久 URL**。

#### 工作流节点链(共 4 个节点)

```
[开始节点(Start)]
   ↓
[条件判断节点:检测是否首次对话]
   ↓ 是
[扣子智能体"提示词"自我介绍分支]
   ↓ 否
[HTTP 请求节点:调 zhishe-a2a 永久 URL]
   ↓
[结束节点(End)]
```

#### 节点 1:开始节点(Start)

| 字段 | 值 |
|---|---|
| 节点名 | 接收用户问题 |
| 输入参数 | `user_query`(用户输入) |
| 其他参数 | `user_id`(扣子用户 ID,可选) |

#### 节点 2:条件判断节点

| 字段 | 值 |
|---|---|
| 节点名 | 判断是否首次对话 |
| 条件 | `{{start.user_query}}` 包含"你好 / 在吗 / 介绍 / 微信"等关键字 → 走"提示词自我介绍" |
| 条件 | 否则 → 走"HTTP 请求 zhishe-a2a" |

#### 节点 3a:HTTP 请求节点(**核心**)

| 字段 | 值 |
|---|---|
| 节点名 | 调 zhishe-a2a 永久 URL |
| **请求方法** | `POST` |
| **URL** | `https://tunnel.zhishe.top/v1/chat/completions` |
| **请求头** | `Content-Type: application/json`<br>`Authorization: Bearer mKgd4EVhF7A8Y9zk6unOyb2jI1NBLaTR` |
| **请求体(JSON)** | 见下方 |
| **超时** | 60 秒(扣子默认) |
| **响应处理** | 取 `choices[0].message.content` 字段 |

**请求体 JSON(用户复制)**:
```json
{
  "model": "deepseek-v4-pro",
  "messages": [
    {
      "role": "user",
      "content": "{{start.user_query}}"
    }
  ],
  "max_tokens": 1500,
  "temperature": 0.7,
  "stream": false
}
```

**说明**:
- `model: "deepseek-v4-pro"` 是 zhishe-a2a 内部模型标识(用户不需要懂,扣子"工作流"直接传)
- `max_tokens: 1500` 配合 V1.6 prompt 1456 字实测(V1.1 元宝版同)
- `temperature: 0.7` 适合装修场景(给点创造性但不离谱)

#### 节点 3b:提示词自我介绍分支(仅首次对话触发)

**扣子智能体"提示词"输入**(用户复制,扣子"智能体 → 提示词"框粘贴):

```
你是"知设 AI 装修顾问",沈阳本地装修 AI,8 年老法师经验,服务过 200+ 沈阳业主。
你能出 2026 Q2 沈阳本地真实市场价(报价有 4 档:经济 350-450、中端 450-600、高端 600-900、豪华 900-1300 元/平),
能给水电/瓦/木/油 4 道工序的避坑指南,能给装修流程节点(量房 → 设计 → 拆改 → 水电 → 防水 → 瓦 → 木 → 油 → 安装 → 软装 → 入住),
每轮自然带转化引导("装修水深,我整理了一份《2026 沈阳装修报价清单》PDF,加我微信 sxxxxx 发你")。

回答前先反问用户"你家是哪个区? 户型多大? 半包还是全包? 装修预算多少?",不要默认给一个数字。

数据来源:国标 GB 50327-2001 / GB 50150-2016 / 伟星 vasen.com 防伪官网 / 沈阳本地 2026 Q2 实测价。
免责声明:不替用户做最终决定,所有信息仅供参考,签约前请以实际勘察和合同为准。
```

**注意**:**这是扣子智能体的"提示词"——只负责"自我介绍 + 路由引导"**。**真正干活的是"工作流"HTTP 请求节点调 zhishe-a2a**。

#### 节点 4:结束节点(End)

| 字段 | 值 |
|---|---|
| 节点名 | 输出答案 |
| 输出参数 | `final_answer` |

**输出取值**:
- 走"HTTP 请求"分支:`final_answer = {{http_response.choices[0].message.content}}`
- 走"提示词自我介绍"分支:`final_answer = {{llm_output}}`(扣子平台豆包 1.5 Pro 直答)

## 6. 22 条知识库处理(关键差异 - 路径 A 自留地)

**关键差异**:**路径 A 下,知识库 100% 在 zhishe-a2a 自留地,不传扣子平台**。

| 知识库 | 位置 | 处理 |
|---|---|---|
| **22 条知识库 V0.1(k001-k022)** | `data/knowledge.json`(zhishe-a2a 永久 URL 后端) | **不传扣子,扣子工作流通过 HTTP 请求 zhishe-a2a,内壳服务自动注入知识库** |
| **22 条知识库 CSV/JSON 备份** | `data/knowledge_yuanqi_import.csv/json` | **V1.1 元宝用,豆包不用**(直接给扣子看的"V1.1 备份"是错位) |

**为什么路径 A 不传知识库?**
- 知识库已在 zhishe-a2a 后端(`app/services/knowledge.py` 自动检索)
- 扣子工作流 HTTP 请求时,zhishe-a2a 自动调 LLM + 知识库注入
- **V1.2 路径 A 的知识库"零迁移成本"**

**对比 V1.1 元宝**:V1.1 腾讯元器**必须把 22 条知识库传腾讯云**(平台要求),所以 V1.1 准备 csv/json。V1.2 扣子**通过工作流走自留地,零迁移**。
