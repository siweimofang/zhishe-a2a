## 一、一句话战略

zhishe-a2a 后端统一引擎不变,只在外层加 4 个平台外壳(千问 / 小艺 / 微信 / 小红书),4 个外壳平行并联,每个外壳独立跑数据,数据验证通过才开下一个,数据验证不过就停。
*(出处:用户原话,2026-06-15;与 PROJECT_CONTEXT L17"主体 = 后端统一引擎(100% 复用,不动),外壳 = 各个平台入口(平行并联,各自加适配层)"完全一致)*

**核心约束:永远只同时管 1-2 个外壳**。开新外壳的同时,旧外壳必须转入"维护态",否则运营成本会击穿一个人的精力上限。

## 二、为什么要这么干

### 2.1 理论支撑:HDC 2026 鸿蒙智能体框架 2.0"意图即服务"

华为开发者大会 2026 上,鸿蒙智能体框架(HMAF)2.0 的官方架构原话:

- **"后端统一引擎+前端多平台获客"** —— 一个大脑,多个入口
- **"意图即服务"(Intent-as-a-Service)** —— Agent 不是用户主动找的,是用户表达意图后被平台分发调起
- **"日均 Agent 分发量过去一年提升 4.5 倍"** —— 验证 Agent 时代流量红利真实存在

zhishe 的战略方向与华为完全同构:zhishe-a2a 就是"后端统一引擎",千问 / 小艺 / 微信 / 小红书 4 个外壳就是"前端多平台获客"的入口载体。
*(出处:HDC 2026 原文,引用见 PROJECT_CONTEXT L61"战略出处:HDC 2026 鸿蒙智能体框架 2.0'意图即服务'+'前装多入口分发'")*

### 2.2 商业现实约束

1 个公司主体养不起 4 个完整 Agent 团队(每个团队需要:产品 1 + 后端 1 + 前端 1 + 运营 1 ≈ 4 人 × 4 团队 = 16 人)。

但 1 个后端 + 4 个外壳可行:
- 后端:zhishe-a2a 已经写完,32 测试全绿(PROJECT_CONTEXT L78)
- 外壳:每个 1-8 小时工作量(接协议 + 写适配层),不需要单独招团队
*(出处:PROJECT_CONTEXT L46-L51 工作量表)*

### 2.3 防止"累死"原则

4 个外壳同时跑 = 4 个 LLM 配额 + 4 个鉴权配置 + 4 套运营话术 + 4 个数据看板 + 4 个平台审核跟进。一个人撑不住。

所以原则是:**每个外壳独立验证数据,数据好才开下一个,数据差就停**。即使第 1 个外壳数据烂,也只损失 1 个;不会因为同时铺 4 个导致 4 个全废、精力耗尽。
*(出处:用户原话,2026-06-15)*

## 五、为什么外壳是"平行并联"不是"主备"

"主备"意味着 1 个主流量入口 + 1 个备份,出问题才切。zhishe 的 4 个外壳不是这种关系,理由:

### 5.1 入口价值独立

每个外壳代表一个独立的用户发现路径,流量不重叠:

| 外壳 | 用户路径 |
|---|---|
| 千问版 | 主动搜"知设" / "沈阳装修" |
| 微信版 | 公众号文章阅读 / 朋友圈分享 |
| 小红书版 | 搜索"沈阳装修" / 信息流推荐 |
| 小艺版 | 鸿蒙系统意图识别(说"我要装修"被分发) |

如果只留 1 个主 + 1 个备,损失的是 3 条独立流量通道。

### 5.2 协议层完全不依赖

| 外壳 | 协议 |
|---|---|
| 千问版 | A2A 0.2.5 |
| 小艺版 | MCP + HMAF |
| 微信版 | OpenAI-compatible `/v1/chat/completions` |
| 小红书版 | 小红书 OpenAPI(评论 / 私信 webhook) |

4 个协议层互不依赖。一个出问题(比如百炼下架入口)不影响其他 3 个。

### 5.3 LLM 解耦

| 外壳 | 外壳侧 LLM | 主体侧 LLM(若调) |
|---|---|---|
| 千问版 | Qwen-Plus-Latest(百炼自带) | - |
| 微信版 | DeepSeek-v4-pro | DeepSeek-v4-pro |
| 小红书版 | DeepSeek-v4-pro | DeepSeek-v4-pro |
| 小艺版 | Pangu / DeepSeek | DeepSeek-v4-pro |

千问和小艺这 2 个壳根本不走 zhishe-a2a 的 LLM 调用层(它们自己有 Qwen / Pangu),zhishe-a2a 在这两个壳里要么完全不被调(V1.0 千问现状),要么只作为工具调用后端(小艺"自定义能力"模式)。其他 2 个壳(V1.1 微信 / V1.2 小红书)走 zhishe-a2a 调 DeepSeek。

### 5.4 运营独立

| 外壳 | 用户活跃时间 | 客服话术 | 转化漏斗 |
|---|---|---|---|
| 千问版 | 全天分散 | 通用装修问答 | 搜 → 答 → 加微信 |
| 微信版 | 推送触达时段 | 文章话题延伸 | 文章 → 对话 → 加微信 |
| 小红书版 | 晚上 8-11 点 | 种草 + 避坑 | 笔记 → 评论 → 私信 → 加微信 |
| 小艺版 | 鸿蒙系统时刻 | 意图上下文承接 | 意图 → 答 → 加微信 |

运营动作完全独立,不能统一模板。

### 6.2 数据门槛定义

- **加微信率**:从外壳进入对话 → 加你微信的人数 / 总进入对话人数。低于 30% 意味着外壳流量质量不行,或 prompt 转化话术没起作用。
- **调起率**:平台分发到这个 Agent 的次数 / 平台总 Agent 机会。低于 5% 意味着上架位置差或关键词匹配差。
- **对话完成率**:用户发起对话后,完整跑完一轮问答(得到装修报价或建议)的比例。低于 60% 意味着用户体验卡顿。
- **私信咨询数**:小红书特有。从笔记/评论进私信的人数,衡量种草效果。

### 6.3 节奏硬约束

**核心约束**:**永远只同时管 1-2 个外壳**。新外壳开 1 个旧的就要转入"维护态"。

"维护态"定义:
- 不主动运营内容(不写新文章、不做新笔记)
- 只监控服务可用性(云函数报错率、外壳 webhook 通不通)
- 不再追加新功能(只修 bug)

理由:1 个人精力上限 = 2 个外壳(1 个开发 + 1 个运营)。4 个并行 = 每个都做不好。

*(出处:用户原话 2026-06-15 + PROJECT_CONTEXT L44-L51)*

## 九、风险与对策

### 9.1 Cloudflare WAF 拦非浏览器 UA(高优先级)

**现象**:Cloudflare 默认 WAF 会拦掉非浏览器的 User-Agent(比如 `python-httpx/0.27.2`),返回 403。
**影响**:公众号 webhook 调用 `https://tunnel.zhishe.top/v1/chat/completions` 时,会被 WAF 拦掉,V1.1 微信接不进来。
**对策**:
1. Cloudflare Dashboard → `tunnel.zhishe.top` 域名 → Security → WAF → Custom Rules
2. 加规则:当 `User-Agent` 包含 `python-httpx` 或 `python-requests` 时,Skip 所有剩余规则(直接放行)
3. 或:在 path `/v1/chat/completions` 和 `/wechat/callback` 加 Bypass
**工作量**:15 分钟
**触发条件**:V1.1 启动前必须先修

*(出处:PROJECT_CONTEXT L99 Cloudflare 已配置,但 WAF 规则细节未列;用户原话 2026-06-15)*

### 9.2 千问品牌 Agent 入驻新政

**现象**:阿里云百炼 2026 改版后"三方 Agent"入口不显示,品牌 Agent 入驻可能有新政策。
**影响**:zhishe-a2a 当大脑(数据护城河 = 1)的路径暂时走不通。
**对策**:
1. 等 2026-06-03 新政开放(PROJECT_CONTEXT L81, L150)
2. 工单话术已写入 `千问接入指南.md`(PROJECT_CONTEXT L238)
3. 临时方案:千问 V1.0 占坑(Qwen 直营)继续跑,微信/小红书先拿数据
**工作量**:工单提交 30 分钟,等待回复 1-3 月
**触发条件**:V1.1 数据跑出来后,看是否值得切回千问走数据护城河

*(出处:PROJECT_CONTEXT L80, L150, L238;用户原话 2026-06-15)*

### 9.3 小艺版 LLM 冲突

**现象**:用户原话"主体用途是接入千问大模型",但小艺生态默认 Pangu/DeepSeek,小艺用户期望 Pangu 回答。
**影响**:如果小艺版强行把对话全交给 zhishe-a2a 的 DeepSeek,用户体验割裂(用户说"你好小艺",回答语气像 Qwen);如果走 Pangu,小艺上架审核可能要求"自研 LLM 不能用第三方 prompt"导致被拒。
**对策**:
1. 优先尝试"自定义能力"模式:小艺负责意图分发 + 兜底回答,Pangu 跑主体,zhishe-a2a 只在"装修专业问题"时作为 tool 被调
2. 被拒则降级"原生 Agent + 工具调用":Agent 在小艺侧跑 Pangu,只把"沈阳装修报价/沈阳装修避坑"这类问题路由到 zhishe-a2a
3. 数据上看:小艺版加微信率低于其他壳 50% 时,放弃"全量转 DeepSeek"的执念
**工作量**:选型讨论 1 小时,实现 2 小时
**触发条件**:V1.3 启动前对齐

*(出处:PROJECT_CONTEXT L11 + 用户原话 2026-06-15)*

### 9.4 每个外壳运营成本
