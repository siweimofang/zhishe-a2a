# Gotchas 创造模式规格说明 v1.0（P3）

**日期**：2026-08-17 | **版本**：v1.0（规格稿，待评审）
**承接**：《Gotchas引擎可逆副作用实现方案_v0.1.md》P3 阶段；前置 Harness-R1 路线图已归档（docs/harness_r1_editor_analysis_20260809.md，原编号情报-04）
**理论依据**：情报-15（DSH 论文：可逆副作用/余效应/汇流性，v0.1 已实现）+ Harness-R1 三原则（改进者不必比被改进者强 / 改得窄一点 / Agent 与 Harness 收益叠加）
**定位**：创造模式 = 自演化 Agent 的运行时基础——让系统在进程内存中现场创建临时规则/临时钩子，验证有效后可固化落盘，无效则回滚丢弃，全程可审计。**"Gotchas 库 = 装修行业的 Harness-R1"。**

---

## 一、目标与范围

### 1.1 目标

1. **临时规则**：运行时创建（内存生效，秒级），重启/reload 即失，不污染持久库
2. **临时钩子**：运行时挂载（可回滚注销），天然不落盘
3. **创造闭环**：创建 → 独立验证 → 固化（落盘）/ 丢弃（回滚），全生命周期留痕
4. **决策约束**：临时规则只能从检索失败/真实场景提炼，不能凭空生成（蒸馏禁区运行时边界）

### 1.2 非目标（明确不做）

- 不做 RL 训练编辑器（Harness-R1 论文的 Phase3，远期另行立项）
- 不做 Agent 自动触发调度器（P3-3 决策层，需独立规格）
- 不改动 v0.1 的持久规则语义（现有 add/update/remove/rollback 行为不变）

---

## 二、与现有 v0.1 的映射（复用清单）

| 现有能力 | 复用方式 | 说明 |
|---|---|---|
| RuleManager.add_rule | 临时规则的载体 | 只改缓存+mark_dirty，天然不落盘 |
| EffectRegistry（LIFO 逆函数累加器） | 临时规则的撤销通道 | rollback/rollback_batch 直接复用 |
| HookManager.register | 临时钩子的载体 | 本身是可逆副作用，无需新机制 |
| set_data() 内存直通 | 检索即时命中 | 汇流性保证索引自动重建 |
| persist() 显式落盘 | 固化的唯一入口 | 加过滤参数（见 F1） |
| P2 面板/事件流 | 审计可视化 | 临时规则全生命周期留痕展示 |
| UNLOADING R1 | 卸载期拒收临时创建 | 复用现成守卫 |

**核心洞察**：v0.1 的"热更新不落盘"与"临时规则"天然同构——P3 的机制层增量是**语义标记**，不是新机制。

## 三、功能规格

### F1 临时规则

| 编号 | 规格 | 说明 |
|---|---|---|
| F1-1 | 创建：`POST /gotchas/admin/rules` 增加 `temp: bool = False` 参数 | temp=true 时 Effect 自动打 `batch_id="temp:<ts>"`，detail 标记"临时" |
| F1-2 | 持久化过滤：`RuleManager.persist(path, include_temp=False)` | 默认写入前过滤 temp 批次；固化才携带（见 F4） |
| F1-3 | 生命周期：进程内存；`restart`/`reload` 即失 | reload 从磁盘重载覆盖缓存，temp 规则随之消失——这是"临时"的语义，不是缺陷，需在面板状态卡展示"临时规则数" |
| F1-4 | 容量上限：temp 批次规则总数 ≤ 50 条 | 防 Agent 失控创建；超限返回 429/400 并记事件 |
| F1-5 | 命名约束：ku_id 不得以 GZ- 前缀开头 | 保留 GZ- 前缀给持久规则，临时规则用 `TMP-<ts>-<seq>`，与业务库天然隔离、回归统计自动排除 |
| F1-6 | 可选 TTL（v1.0 不做，v1.1 评估） | 24h 自动过期回滚，需新增定时扫描 |

### F2 临时钩子

| 编号 | 规格 | 说明 |
|---|---|---|
| F2-1 | `POST /gotchas/admin/hooks` 注册临时钩子（point/fn 描述/deps/name） | 运行时注册返回 effect_id，可精确回滚注销 |
| F2-2 | 钩子本来就不落盘（重启即失），temp 标记仅用于审计归类 | 与 F1 共享"temp"语义，事件流可筛选 |
| F2-3 | 临时钩子上限 10 个 | 防止抢占管线；protected 系统钩子不受影响 |

### F3 创造闭环 API

```
① 创建  POST /gotchas/admin/rules  {ku, temp:true}          → effect_id, state=APPLIED
② 验证  POST /gotchas/admin/rules/{ku_id}/verify             → 自动检索验证（独立于创造）
       返回: {"hits": [...], "self_hit": bool, "collateral": int}
       self_hit=新规则是否命中目标问法; collateral=同问法下命中条数变化(误伤检测)
③ 固化  POST /gotchas/admin/rules/{ku_id}/finalize          → 门槛: ②通过 + 人工确认标志
       动作: 从 temp 批次移除标记 → persist(include_temp=False) → 事件留痕 finalize
④ 丢弃  POST /gotchas/admin/rollback {batch_id:"temp:..."}  → 复用现成批次回滚,零残留
```

| 编号 | 规格 | 说明 |
|---|---|---|
| F3-1 | 验证独立于创造（改进清单 A 落地） | verify 由系统检索器执行，不走 Agent 自评 |
| F3-2 | 固化必须验证先行 | 未 verify 或 self_hit=false → finalize 拒绝（400） |
| F3-3 | 固化需人工确认 | `confirm: true` 参数；无人工标志则返回 403——蒸馏禁区红线：禁止自动固化（见 §五） |
| F3-4 | 固化后规则转为持久（batch_id 置空），可被正常 update/remove/rollback | 与 v0.1 行为完全一致 |

### F4 面板与审计

| 编号 | 规格 | 说明 |
|---|---|---|
| F4-1 | 状态卡新增"临时规则 N/50"与"临时钩子 N/10" | P2 面板增量 |
| F4-2 | 事件流新增事件类型：temp_created / temp_verified / temp_finalized / temp_dropped | 全生命周期留痕（P2 面板类型筛选扩展） |
| F4-3 | `/gotchas/admin/status` 增加 temp 统计字段 | 保持接口向后兼容（新增字段不破坏旧客户端） |

### F5 决策层规则（Harness-R1 三原则落点）

| Harness-R1 原则 | 运行时落点 | 校验器实现 |
|---|---|---|
| 改进者不必比被改进者强 | 临时规则不要求模型变强，只要求场景变准 | verify 只看命中与误伤，不看模型能力 |
| **改得窄一点** | 临时规则必须场景化精准 | `窄规则校验器`（F5-1）：question 过短（<8 字）、含"注意""小心""安全"等宽泛词的拒绝创建，与论文"Buy Now 拦截"同型——从负样本学分寸，此处先用静态规则替代 |
| Agent 与 Harness 收益叠加 | 多临时规则可叠加生效、可独立回滚 | 天然支持（独立 batch 独立 effect） |

| 编号 | 规格 | 说明 |
|---|---|---|
| F5-1 | 窄规则校验器：创建时静态校验（关键词/长度），校验不过 → 400 + 提示改窄 | v1.0 用静态规则；RL 动态学分寸 = Harness-R1 论文 Phase3，另立项 |

## 四、实施计划（分三子阶段，各自可独立上线）

| 子阶段 | 内容 | 交付物 | 前置 | 预估 |
|---|---|---|---|---|
| P3-1 机制层 | F1（temp 标记/persist 过滤/上限/命名约束）+ F2-1/2 + 测试 | temp 规则/钩子可创建可回滚，不落盘 | 无（v0.1 之上纯增量） | 2-3 天 |
| P3-2 闭环层 | F3（verify/finalize）+ F4（面板/状态扩展）+ 演练脚本扩展 | 创造闭环可用，面板可审计 | P3-1 | 2-3 天 |
| P3-3 决策层 | F5-1 窄规则校验器 + 人工固化流程 + （远期）Agent 触发 | 自演化 Agent 基础 | P3-2 | 2 天 + 远期 |

**注**：P3-3 的"Agent 自动触发"依赖独立的 Agent 调度器规格（Harness-R1 编辑器模式的知设版），不在本规格内实现。

## 五、边界与红线（蒸馏禁区运行时边界）

1. **禁止自动固化**：finalize 必须带人工确认标志（F3-3）——临时规则只能由 Agent 从检索失败/真实场景提炼，固化的最终裁决权在人
2. **禁止凭空创建**：temp 规则创建同样受"窄规则校验器"约束（F5-1），宽泛/幻觉式规则在创建时即拦截
3. **容量即防线**：50 规则/10 钩子上限，超限拒绝并记事件（可观测）
4. **temp 不持久**：persist 默认过滤 temp；任何路径不得把 temp 规则写入 all_ku.json（含 reload 意外路径——reload 前若存在未固化 temp 规则，返回警告响应体提示"N 条临时规则将被清空"）
5. **审计兜底**：所有 create/verify/finalize/drop 事件进 registry 历史（P2 面板可见），违规操作可回滚、可追溯

---

## 六、验收标准

1. **临时性**：temp=true 创建规则 → 检索命中 → 重启（或 reload）→ 检索消失，all_ku.json 无该规则
2. **持久化隔离**：persist() 后临时规则不在磁盘；finalize 后 persist 在磁盘
3. **验证先行**：未 verify 或 verify.self_hit=false 的 finalize → 拒绝
4. **人工门槛**：finalize 无 confirm=true → 403；有 → 成功且事件留痕 temp_finalized
5. **窄规则**：宽泛 question（如"注意装修安全"）创建 → 400 拦截
6. **容量**：临时规则第 51 条 → 拒绝；第 50 条 → 允许
7. **零污染回归**：temp 规则存在期间跑 615 问法回归 → 与 baseline 一致（temp 批次回滚后无残留）
8. **审计**：面板事件流可完整回放某 temp 规则的 created→verified→finalized/dropped 全链路

## 七、风险与待决策项

| 项 | 类型 | 说明 |
|---|---|---|
| reload 清空 temp 规则 | 行为确认 | 规格按"reload 即失"设计（临时语义），若实际需要 reload 保留需另加机制（不建议，违背"临时"定义） |
| verify 的 collateral 阈值 | 待决策 | 误伤检测阈值（建议：目标问法下新增命中 >2 条即判误伤）——上线前用演练脚本实测校准 |
| 窄规则校验器词表 | 待决策 | 宽泛词初始词表（注意/小心/安全/应该/必须等）由人工维护，后续可按事件数据扩充 |
| Agent 触发层 | 远期 | 依赖独立规格（Harness-R1 编辑器模式知设版），本规格不覆盖 |

---

**设计原理一句话**：让 v0.1 的"可逆副作用"长出一个"临时区"——Agent 在内存里大胆创造、系统独立验证、人工决定固化，坏想法随时回滚零残留，好想法一步落盘——这就是装修行业 Harness-R1 的运行时形态。
