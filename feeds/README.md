# feeds — 知识库投喂项目

知设知识库的统一投喂入口。所有书籍、思想体系、行业前沿理念的投喂都走这套流程。

## 两层结构（重要）

**灵魂层 = 投喂蒸馏方法（01–04 环节），跨板块通用**：不管投喂哪个板块的知识库，蒸馏流程都是同一套——原稿 → 评估 → 条目 → 思想层。板块不占据目录层，只以文件名前缀（如 `新媒体运营_xxx`）和 category 标签贯穿其中。

**板块层 = 各知识库自己的组织框架**：每个板块有自己内部的框架体系（例：《新媒体运营》8 模块：心理学与哲学 / 定位与人设 / 内容创作与多平台适配 / 视觉与视频内容生产 / 热点捕捉与趋势洞察 / 账号诊断与运营优化 / 变现与商业闭环 / 工具与效率）。板块框架文档作为思想层产物存放在 `04_思想层提炼/`，归档时体现为 knowledge.json 的 `category` + `tags`。

## 知识库本体

- 条目库：`../data/knowledge.json`（热加载，改完即生效，无需重启）
- 条目格式：`{id, category, tags, question, answer}`
- 检索方式：`knowledge.py` 关键词检索 top3 注入 prompt
- 原文库：`../data/knowledge_src_cvf.json`（2026-08-11 起，双层入库）
  - 全书/全文按投喂批次切块存原文（如《选择、价值与决策》122 块）
  - 检索方式：`knowledge.py` 的 `search_src`（jieba 分词核心词 + 滑动窗口加分），命中 1 块注入 prompt 作为参考原文
  - 原文为扫描识别，注入时带「个别字词可能有误」提示

## 投喂闭环（五步）

1. **投喂原稿** → `01_原稿/<日期>_<书名或体系名>/`
   用户提供原始资料或提炼稿，原样存档，不改写。
2. **评估报告** → `02_评估报告/`
   我产出：前沿度诊断 + 三类知识缺口清单（理论/基础/体系）+ 解锁映射。
   单篇文章按模板：文章名 + 双打分制（X/10 和五星）+ 四维标准（AI的技术理解与路径思考/改变认知/长期有效/与我的方向关联契合度）+ 第一性原理 + 总结 + 级别（L1/L2/L3 建议入库）。
3. **待入库条目** → `03_待入库条目/`
   把缺口转成 knowledge.json 格式的条目草稿（json 文件，逐条可审）。
4. **入库对接** → 校验后合并进 `../data/knowledge.json`
   合并前自动备份；id 去重、字段校验；条目审核通过才入库。
   入库前过「蒸馏禁区」自查（见下节）。
5. **思想层提炼** → `04_思想层提炼/`
   内容层（用户投喂）→ 思想层（我提炼 prompt 原则），沉淀为提示词方法论。

## 蒸馏禁区（知识来源铁律，2026-08-11 写入项目总宪章第九节）

知设的核心资产=行业认知，必须像基础模型能力一样自积累，禁止「蒸馏」：

- 知识来源三通道（只允许这三条路）：权威文献/书籍原文（走本闭环）、真实业务场景（谈单/工地沉淀 Gotchas）、用户投喂语料（内容层）
- 禁止项：❌ 大模型直接生成行业条目入库；❌ 竞品话术/公开文案转录入库；❌ 只存提炼结论丢弃原文（双层入库：原文层保真+知识层生长）
- 自查：条目出处可追溯？提炼基于原文/场景而非模型凭空生成？原文层完整保留？

## 分工约定

- 用户：沟通前沿思想理念（内容层），补齐条目内容
- 我：产出评估报告、提炼 prompt 思想层、执行入库对接
